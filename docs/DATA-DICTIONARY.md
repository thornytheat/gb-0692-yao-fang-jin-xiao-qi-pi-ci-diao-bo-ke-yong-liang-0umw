# 数据定义

FEFO仅分配到店后剩余有效期满足需求的库存；冻结量先扣，拆包需整包装，召回批不得调拨。

输入字段：record, kind, sku, lot, qty, frozen, pack, expiry, store, min_days, arrival, version, status。所有ID按字符串保留；空字符串、NULL、N/A、未知与“-”视为缺失，不能当作数值零。数值使用Decimal，输出为十进制字符串。重复业务键相同内容计重复，内容冲突隔离或按明确修订号裁决，不按文件顺序盲目覆盖。业务键定义为：库存行取(kind, record, sku, lot)，需求行取(kind, record, sku)。同一单据的多条需求必须药品不同；同单同药品重复行按内容判重或隔离为冲突。

每条证据有原始行号，隔离记录有原因码及原值。时间区间使用半开边界；日期定义在各模块规则内显式声明。输入表头可调序，不得缺列或重复；中文旧编码可上传。规则版本存入运行清单，重跑使用原始文件内容摘要与规则版本共同确定幂等键。复核使用revision乐观锁，陈旧提交返回409。

订单口径：同一record的多条demand行组成一张补货单，多条为成套单、单条为散单。成套单整单原子分配，任一行按净需求无法凑齐则整单不确认、不占用任何批次；散单允许部分补货。status为urgent/急单/紧急/加急时视为急单，急单先在策略下优先占货。

策略：urgent_first（急单先）按急单、到货日、门店、单据排序；set_first（成套先）按成套、急单、到货日、门店、单据排序。策略写入运行清单parameters，并参与run_id；同文本不同策略为不同批次，同一策略重试复用原批次。

qty为库存件数或需求申请件数。frozen在stock行是冻结量，在demand行是门店已有可用量。库存先扣冻结，再按整包装向下取整；不能跨药品调拨。到期日当天不可用，剩余有效天数等于要求值时允许。缺口不自动改成零。截止日固定2026-11-18，便于复现。
